# Internationalization

Localize parameter names, string values, and menu items on the way into the host and delocalize them on the way out.

## Overview

``FxGripI18N`` is an extension in the notification-driven system described in
<doc:ExtensionArchitecture>. The extension maps a parameter's name, string value, and menu
items through the plugin bundle's `Localizable.strings` as they pass through the parameter
API. A write localizes a key to its display string; a read delocalizes the display string
back to the key, so a round-trip closes. The loader installs the extension when
`isInternationalized` reads the plugin property as `YES`.

The forward table is the plugin's own bundle, `localizationBundle`, not the host's main
bundle. `NSLocalizedString` reads the main bundle, which is the host application inside an
out-of-process FxPlug plugin. The forward table is cached; the reverse table is built on first
delocalization by inverting the forward table.

## The API notification handlers

``FxGripI18N`` is the worked consumer example in <doc:ExtensionArchitecture>. It rewrites the
nested parameter dictionary on the parameter API notifications:

| Notification handler | Direction | Text |
| --- | --- | --- |
| `extAPIParameterSetNamePre:` | localize | name |
| `extAPIParameterGetName:` | delocalize | name |
| `extAPIParameterSetStringValuePre:` | localize | string value |
| `extAPIParameterGetStringValue:` | delocalize | string value |
| `extAPIParameterSetMenuPre:` | localize | menu items |
| `extAPIParameterGetMenu:` | delocalize | menu items |
| `extAPIParameterAdd:` | localize | name, and the value or items of a String or Menu |

The handlers read the payload keys directly, because the API payloads do not always carry the
type and name the guarded dictionary accessors require.

## Direction switches

Each direction has an independent switch per text kind: `isLocalizingNames`,
`isLocalizingValues`, `isLocalizingMenus`, `isDelocalizingNames`, `isDelocalizingValues`, and
`isDelocalizingMenus`. The localize switches default to `YES`. The delocalize switches are
read from the plugin properties at load: an unset values switch defaults to the names switch,
and an unset menus switch defaults to the values switch.

## Utilities

- `localize:` maps a key to its localized string, returning the key unchanged when the table
  has no entry.
- `delocalize:` maps a localized string back to its key by inverting the table.
- `parameter:name:` reads a parameter's name through the dynamic API and delocalizes it when
  name delocalization is enabled.
